# technical-documentation

## Purpose
Maintain concise, accurate engineering and delivery documentation.

## When to use
Architecture, decisions, tasks, APIs, and submission work.

## Required inputs
Verified implementation, test outputs, ADR decisions.

## Workflow
1. Read root `AGENTS.md` and relevant requirements.
2. Inspect current code/data before proposing changes.
3. Confirm scope, dependencies, and file ownership.
4. Implement or analyze only the assigned scope.
5. Add evidence, tests, and documentation.
6. Submit a completion report.

## Rules
- Do not document intended behavior as implemented unless verified.
- Link requirements/tasks/ADRs.
- Record limitations honestly.
- Keep challenge writeup <= one page.

## Expected outputs
Updated docs, ADRs, README, WRITEUP.

## Verification
Cross-check docs against code and actual command outputs.

## Completion standard
Do not report completion until the required outputs exist and verification results are truthful.
