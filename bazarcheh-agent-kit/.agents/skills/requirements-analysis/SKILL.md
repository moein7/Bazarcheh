# requirements-analysis

## Purpose
Translate business requirements into traceable technical requirements and acceptance criteria.

## When to use
At project kickoff and whenever requirements change.

## Required inputs
Original challenge, current behavior, data schema.

## Workflow
1. Read root `AGENTS.md` and relevant requirements.
2. Inspect current code/data before proposing changes.
3. Confirm scope, dependencies, and file ownership.
4. Implement or analyze only the assigned scope.
5. Add evidence, tests, and documentation.
6. Submit a completion report.

## Rules
- Preserve explicit inequalities and quantities.
- Separate fixed requirements from assumptions.
- Identify ambiguity and ask the orchestrator.
- Link requirements to tasks and tests.

## Expected outputs
Requirement IDs, gap analysis, acceptance criteria.

## Verification
Every mandatory requirement maps to implementation status and a verifiable test.

## Completion standard
Do not report completion until the required outputs exist and verification results are truthful.
