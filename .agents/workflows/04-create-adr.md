# Workflow: Create or Update an ADR

Create an ADR when a decision affects architecture, business semantics, security, reliability, API/CLI contracts, data handling, or a meaningful trade-off.

1. Search existing ADR index for related decisions.
2. Describe context and evidence.
3. State one precise decision.
4. Compare realistic alternatives.
5. Explain consequences, risks, and affected modules.
6. Define verification.
7. Mark status Proposed.
8. Ask orchestrator to review.
9. Only orchestrator may mark Accepted.
10. Update ADR index and link related requirements/tasks.

Do not create an ADR for trivial implementation details.
